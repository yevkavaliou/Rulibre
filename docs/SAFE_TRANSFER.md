# Безопасная передача книги

Проблема №12, 12 октября 2026 года.

## Контракт

`DeviceState::send_book` и `send_book_with_options` сохраняют прежние сигнатуры.
Они перепроверяют выбранный том до подготовки, сохраняют защиту библиотеки
из этапа №7 и вызывают новый модуль `transfer`.

`send_book_cancellable(book_path, author, options, cancel)` передаёт общий
`converter::CancellationToken` в обнаружение конвертеров, подготовку и копирование.
`prepare_file_cancellable` доступна отдельно. Слой фоновых заданий остаётся №13.

`transfer::transfer_file(file, device, author, cancel, progress)` принимает уже
подготовленный файл и возвращает `Result<PathBuf, Error>`. Владелец `PreparedFile`
должен оставаться живым до возврата. Progress получает реальные скопированные байты
и исходный размер после каждого блока 64 KiB; публикация следует после копирования.
Прежние клиенты получают ошибки через существующие адаптеры сообщений.

## Проверка назначения

Перед записью, между блоками и непосредственно перед публикацией ядро получает
актуальный список томов. Проверяются ID, mount point, тип устройства, файловая
система, доступность и read-only. Для автоматически обнаруженного устройства
повторно проверяются сигнатуры; для ручного выбора используется валидатор №9.
Обычный временный каталог больше нельзя передать публичному API как ридер.
Отсутствующий том отвергается, даже если после размонтирования остался каталог.

Корень никогда не создаётся. Для Kobo создаётся только один каталог автора;
для Kindle используется `documents`. `normalize_component` заменяет разделители,
управляющие символы и запрещённые Windows символы на `_`, убирает крайние пробелы
и конечные точки, заменяет пустое имя/`.`/`..` на `Unknown`, экранирует DOS имена
(`CON`, `NUL`, `COM1`, `LPT1` и др.). Политика применяется также к конечному имени
книги и `Device::books_dir`; Unicode сохраняется. Имя без корректного Unicode
возвращает InvalidInput. Длинные имена не обрезаются: ошибка файловой системы
возвращается вызывающему коду. Разные имена после нормализации могут совпасть —
это обычный конфликт, без автоматического переименования.

Ссылки, junction и reparse points в каталоге назначения отвергаются. На Unix
`mkdirat/openat/unlinkat` работают относительно удерживаемых дескрипторов,
`O_NOFOLLOW` исключает переход через ссылку, проверяется совпадение устройства
файловой системы и текущих dev/inode каталога. На Windows удерживаются handles
корня и назначения без FILE_SHARE_DELETE; проверяются reparse attributes
до и после открытия. Подмена каталога не перенаправляет запись в библиотеку.

## Копирование и конфликты

Создаётся уникальный `.rulibre-<pid>-<counter>.part` через create-new/exclusive
в самом каталоге назначения. Данные пишутся только в него. Проверяются ошибки
чтения/записи, число скопированных байтов, размер временного файла и `sync_all`.
Затем handle файла закрывается и выполняется публикация одного имени:

- Windows: `MoveFileExW` без REPLACE_EXISTING/COPY_ALLOWED.
- Linux: `renameat2(RENAME_NOREPLACE)` относительно дескриптора назначения.
- macOS: `renameatx_np(RENAME_EXCL)` относительно того же дескриптора.

Используются нативные операции без требования hard links, подходящие в том числе
для FAT/exFAT при поддержке системой exclusive rename. Если файловая система
не поддерживает выбранную операцию, передача завершается ошибкой и очисткой;
небезопасного fallback нет. Семантика: [Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw),
[Linux renameat2](https://man7.org/linux/man-pages/man2/rename.2.html).

Существующий файл, каталог или ссылка дают `ErrorKind::Conflict`. Проверка
есть и до копирования, и внутри нативной публикации: появление конкурирующего
файла во время копирования не приводит к его перезаписи. Режима замены нет.
До публикации конечное имя не появляется; после публикации отмена не откатывает
успех. Отмена кооперативная, проверяется между блоками и перед публикацией;
синхронный OS-вызов чтения, записи, flush или обнаружения нельзя прервать токеном.

## Ошибка и очистка

При ошибке или отмене handle закрывается; если исходный том и каталог всё ещё
доступны, частичный файл удаляется. Возвращается исходная ошибка, например
Cancelled, Conflict или Io с операцией и путём. Старый конечный файл сохраняется.
Созданный пустой каталог автора может остаться.

Если проверить устройство или удалить файл нельзя, возвращается
`ErrorKind::PartialTransfer { cause, partial_path, cleanup_error }`.
Сохраняются и причина передачи, и причина неуспешной очистки. Сообщение прямо
указывает возможный оставшийся файл. После отключения наличие файла неизвестно;
при внешнем переименовании каталога записанный путь может устареть. Очистка
на другом томе, появившемся под прежним mount point, не выполняется. После
переподключения удаление указанного `.part` выполняется отдельно; автоматического
удаления старых файлов или возобновления передачи нет.

## Проверки и ограничения

На Windows/NTFS в `target/conversion-tests-temp`:

- `cargo test --locked --offline`: 81 тест прошёл, 3 верхнеуровневых теста
  игнорируются согласно исходной матрице; subprocess-helper проверяется отдельно.
- 10 новых тестов: успешное копирование и опасные имена; конфликт до/во время
  копирования; частичная запись и PermissionDenied; отмена до/во время копирования;
  отсутствующий корень; отключение с диагностикой оставшегося `.part`; изменение
  размера источника; смена ID/read-only/пустой снимок томов; реальная Windows
  блокировка каталога; реальный junction в библиотеку. Снимки подтверждают
  неизменность источников. PermissionDenied при записи и отключение подменены;
  sharing violation и junction проверены настоящими Windows операциями.
- Прежние интеграционные фикстуры адаптированы: публичный send отвергает каталог
  без смонтированного тома, а копирование проверяется приватной подменой снимка.
- `cargo check --locked --offline`: ядро/TUI/scan_metadata прошли.
- Форматирование ядра/TUI прошло. Clippy прошёл с прежним предупреждением
  `collapsible_if` в `metadata.rs`, без новых предупреждений.
- Tauri host check и 3 теста транспорта прошли с временными `icons/icon.ico`
  и `dist/index.html`; оба файла и каталоги удалены после проверки.

Для повторения файловых тестов на Windows нужны выполнение вне sandbox и
TMP/TEMP, направленные в существующий `target/conversion-tests-temp`:
`cargo test --locked --offline`. В sandbox canonicalize/hard links блокируются.

Физическая проверка Kobo/Kindle **не выполнялась**: доступное оборудование не
подтверждено. Реальное выдёргивание USB, FAT/exFAT, поведение firmware и заполненный
диск не проверены. Linux/macOS runtime и Unix тест ссылки/переименования не
выполнялись; установлен только Windows Rust target, WASM также недоступен.

Гарантии относятся к управляемым ошибкам и отмене. Flush файла и переименование
не являются гарантией сохранности файловой системы при потере питания; журнал
каталога после публикации отдельно не синхронизируется. После аварийного завершения
может остаться `.part`. Контроль размера не обнаруживает изменение источника без
изменения длины: источник должен оставаться стабильным во время операции.
Проверки томов — снимки; отключение непосредственно после успешной публикации
не может быть надёжно обнаружено этим вызовом. Коммит/PR не создан.
