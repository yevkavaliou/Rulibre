# Форматы, файлы и идентификация книг

Проблема №5 из `PRE_UI_PLAN.md`, 11 октября 2026 года (Europe/Warsaw).

## Модель и распознавание

`book::Book` содержит `id: BookId`, автора, название, `path: PathBuf` и
`files: Vec<BookFile>`. Каждый `BookFile` содержит точный `PathBuf` и `Format`.
Несколько файлов одного формата сохраняются отдельно. Строки `EPUB, PDF`
формируют только адаптеры TUI и Tauri для отображения и поиска.

Текущий явный список распознаваемых форматов: **AZW3, DOCX, EPUB, KEPUB,
MOBI, PDF, TXT**. Остальные расширения пока не поддерживаются сканером.
Распознавание расширения не проверяет содержимое файла.

KEPUB распознаётся только по `.kepub.epub`, обычный EPUB — по `.epub`.
Регистр ASCII-расширений не имеет значения. Отдельное `.kepub` не принимается.
OPF, обложки JPG/PNG и другие изображения, metadata.db, неизвестные расширения,
каталоги с расширением ebook и файлы с конечными `.tmp`, `.part`, `.bak` не
попадают в список. Имена, начинающиеся с `.` или `~`, также исключаются.
Расширения анализируются без преобразования всего пути в Unicode: native-пути
остаются точными, включая имена, не представимые в UTF-8 на Unix.

`scanner::scan_files` возвращает файлы в порядке **Format → точный native-путь**.
Порядок Format соответствует алфавиту меток. Книги сортируются по автору и
названию без учёта регистра, затем по точному пути для разрешения совпадений.
Результат не зависит от порядка `read_dir`.

Каталог без распознаваемых книг пропускается. Ошибка корня возвращается как
`Err`; ошибки отдельных авторов/книг сохраняются в `ScanReport.warnings`,
сканирование остальных каталогов продолжается. Ошибка чтения файлов книги
не превращается в успешный пустой список.

## Распознавание и допустимость использования

Это три отдельные политики, а не один список расширений:

| Назначение | Текущие форматы |
| --- | --- |
| Распознавание сканером | AZW3, DOCX, EPUB, KEPUB, MOBI, PDF, TXT |
| Вход ebook-convert в текущей политике | AZW3, DOCX, EPUB, MOBI, PDF, TXT |
| Вход kepubify | Только обычный EPUB |
| Готовые файлы Kobo в текущем API | KEPUB, EPUB, в этом порядке |
| Готовые файлы Kindle в текущем API | AZW3, MOBI, в этом порядке |

Политика устройств сохраняет ограниченный список прежнего API; эта таблица
не подтверждает поддержку всех моделей физических ридеров. Проверка реальных
возможностей и маршрутов конвертации относится к №8 и №11.

`converter::find_source_file(&book.files)` выбирает файл из снимка сканирования,
без повторного обхода каталога. Приоритет: обычный EPUB, затем допустимый формат
по алфавиту метки и точный путь. KEPUB не выбирается как обычный EPUB и не подаётся
в ebook-convert. Выбор одинаков при любом порядке переданного списка файлов.
Отсутствие входа возвращает `None`. Прямой `convert` принимает типизированную
цель и отвергает неподдерживаемое расширение источника до запуска процессов.

Цели ebook-convert ограничены EPUB/PDF/MOBI/AZW3/DOCX/TXT. KEPUB предлагается
только при обычном EPUB и доступном kepubify; попытка создать его без подходящего
kepubify возвращает ошибку. Недопустимый прежний fallback в ebook-convert с
расширением `.kepub` удалён. Общий план многошаговой конвертации не реализован.

Передача на устройство пока принимает каталог книги и сканирует его один раз
при подготовке. Затем выбирает файл по типу формата и точному пути; повторное
сканирование нужно только после конвертации, чтобы получить новые файлы.
Прежняя обязательная конвертация EPUB для Kobo остаётся предметом №11.

## Идентификатор

`BookId` имеет область действия одной библиотеки:

- `Calibre(u64)` — положительное число из завершающего суффикса ` (123)` имени
  каталога. Только ASCII-цифры, допустимы ведущие нули. ID сохраняется после
  переноса корня библиотеки или переименования автора/названия с сохранением ID.
- `RelativePath(PathBuf)` — точный относительный путь `автор/каталог книги`, если
  суффикс отсутствует, пустой, равен нулю, содержит нецифровые символы либо число
  не помещается в u64. Такой ID сохраняется при переносе корня, но меняется при
  переименовании каталога. Хеши и случайные числа не используются.

При повторяющемся Calibre ID все видимые книги с таким ID получают относительные
ID и отдельные предупреждения с путями. Ни одна книга не исчезает, выбор не
становится неоднозначным. Проверка дубликатов относится к книгам, успешно
попавшим в текущий отчёт сканирования.

Из названия удаляется только корректный суффикс Calibre ID. Некорректные суффиксы
остаются частью названия. Метаданные OPF и база metadata.db для ID не читаются.

## Сериализация и адаптация клиентов

JSON ядра теперь содержит `id` и `files` вместо строкового `formats`:

```json
{
  "id": { "kind": "calibre", "value": 123 },
  "author": "Author",
  "title": "Title",
  "path": "Author/Title (123)",
  "files": [
    { "format": "EPUB", "path": "Author/Title (123)/book.epub" }
  ]
}
```

Fallback сериализуется как `{"kind":"relative_path","value":"Author/Title"}`.
Разделители путей в JSON соответствуют платформе. Native-путь, который serde
не может представить текстом, вызывает ошибку сериализации, не заменяется
искажённой строкой. Совместимость со старым JSON `Book.formats` не сохраняется;
постоянный кеш книг в приложении отсутствует.

Tauri `DisplayBook` добавляет производную строку `formats`, сохраняя `id`, `files`
и `path`. Чистые типы Format/BookFile/BookId общие с frontend через `book.rs`,
без включения файловой логики ядра в WASM. Команды `target_formats` и
`convert_book` принимают список файлов; `ConvertOk` возвращает `new_files` и
производное `new_formats`. TUI/GUI обновляют записи по ID; ключ списка GUI содержит ID и строку форматов,
чтобы после конвертации Leptos обновлял отображение строки.
После конвертации обновляется весь список файлов, а не только строка отображения.

  охватывают распознавание, файлы одного формата, порядок создания и выбора,
  выбор из снимка после переноса каталога, политики входов/устройств, стабильность

  разделение EPUB/KEPUB при выборе для устройства. Сохранился тест предупреждения
