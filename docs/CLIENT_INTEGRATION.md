## Изменения

TUI использует `JobExecutor::new(2, 16)` для сканирования, чтения метаданных,
проверки конвертеров, конвертации и передачи. Цикл обработки событий опрашивает
каналы через `try_result`, без ожидания завершения операции. Результаты
конвертации связаны с `JobId` и `BookId`; результаты чтения метаданных также
проверяют поколение запроса и текущий режим. Возврат A → B → A не позволяет
первому запросу A заменить новые данные. `Esc` отменяет активную конвертацию.
Сообщения о завершении передачи/конвертации содержат название исходной книги.

В ядро добавлены запросы `Metadata`, `Backends` и `ConvertFiles`. Последний
планирует конвертацию по всему списку файлов внутри worker, сохраняя выбор
источника и правила безопасности прежнего API. `JobId`, состояния и события
выделены в `job_model.rs`, данные метаданных — в `metadata_model.rs`.
Прежние пути импорта `jobs::*` и `metadata::Metadata` сохранены.

Tauri управляет одним `JobService` с теми же ограничениями. Команды
`scan_library`, `convert_book`, `send_to_device` возвращают ID принятого
задания. `poll_job(id)` возвращает `{ id, events, result }`, где `result`
отсутствует до завершения и содержит сериализуемый `Result<JobValue, String>`
после него. Конечный ответ собирается один раз; повторный опрос возвращает
ошибку. `cancel_job(id)` передаёт отмену в ядро. Неполученные результаты
учитываются в отдельном лимите 16 записей. Ошибки блокировок возвращаются
клиенту, а не вызывают `unwrap`.

Чтение метаданных, проверка конвертеров, проверка библиотеки перед сканированием
и создание временного workspace в Tauri вынесены в `spawn_blocking`.
Основные операции выполняются в workers ядра. Принятие задания по-прежнему
может синхронно разрешать пути назначения; это ограничение №13 сохраняется.

Frontend обрабатывает все `invoke` через `Result`: сериализацию аргументов,
отклонение Promise и десериализацию ответа. Binding использует `catch` и для
`invoke`, и для подписки на события. Ошибки подписки/событий показываются через
существующие уведомления. Метаданные проверяют книгу, поколение запроса и
открытую панель. Конвертация дополнительно проверяет поколение своего запуска;
повторный Enter во время операции не создаёт новое задание. Отмена до получения
ID также обрабатывается: поздно принятый запрос сразу получает `cancel_job`.
Диалог показывает этап конвертации, передача — реальные байты копирования.
Повторная отправка формы выбора библиотеки блокируется до окончания запроса.
Старый таймер уведомления не очищает более новое уведомление.

WASM компилирует общие модели книг, конвертеров, устройств, метаданных и заданий
из файлов моделей; файловая логика и зависимость `rulibre-core` в WASM не
подключаются. Совместимость оставшихся представлений `Book`, `Config`,
результатов и отчётов проверяется сериализацией. Новые экраны не добавлены.

Временный workspace принадлежит приложению до завершения задания. После
успешной конвертации он хранится до выхода; после ошибки удаляется. Tauri при
выходе сначала отменяет задания и присоединяет workers, затем освобождает
workspace. В TUI порядок владения обеспечивает то же при `Drop`.

## Проверки и воспроизведение

На Windows/MSVC прошла команда:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-clients.ps1 -WasmIpc
```

Скрипт проверяет:

- `cargo test --locked`: 96 тестов ядра и 3 теста TUI; 3 теста ядра игнорируются;
- `cargo check --locked`: ядро, TUI и `scan_metadata`;
- `cargo check --locked -p rulibre-gui` и 8 тестов Tauri host;
- `cargo check --locked -p rulibre-gui --target wasm32-unknown-unknown`;
- `cargo fmt --all -- --check`;
- сборку WASM с тестовым feature `ipc-smoke`, генерацию binding и запуск Node.js.

Журнал: [client-integration/check.log](client-integration/check.log).
Rust WASM target установлен. Для Node smoke использован `wasm-bindgen-cli`
0.2.108, соответствующий Cargo.lock, установленный в `target/tools`:

```powershell
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.108 --locked --root target/tools
```

Без `-WasmIpc` CLI и Node не требуются. Smoke exports отсутствуют в production
сборке. Node запускает настоящий скомпилированный WASM с синтетическим Tauri API.
Проверены девять сценариев: отклонение Promise строкой и объектом, неверный тип
ответа, Unicode-путь, ошибка сериализации до вызова backend, ожидание и успешный
результат задания, отклонение опроса, чужой JobId и ошибка результата задания.

Native тесты проверяют начальное сканирование через очередь, ошибки сканирования,
смену выбранной книги и A → B → A, завершение и однократное получение результата
через транспорт, совместимость моделей, освобождение workspace при ошибке
конвертации и отказ передачи в обычный каталог с сохранением исходных файлов.
Новый тест ядра проверяет метаданные, ошибочный OPF и отмену запроса в очереди.
Прежние проверки №13, включая копирование с байтами прогресса, также прошли.

Тесты выполнены вне sandbox: внутри него Windows файловые проверки и Tauri
build script получали ошибки доступа. TMP/TEMP ограничены `target` проекта.
Остаются предупреждения о неиспользуемых частях общих моделей на отдельных
целевых платформах и кэше hard links; ошибок сборки нет.

## Ограничения

В репозитории по-прежнему нет готового `dist` и Windows `icons/icon.ico`.
Скрипт временно создаёт минимальные ресурсы только при их отсутствии и удаляет
только созданные им файлы и пустые каталоги. Это проверка host-кода, а не сборка
поставляемого GUI. Существующие ресурсы скрипт не перезаписывает.

Настоящий WebView, диспетчер Tauri IPC в запущенном приложении, Trunk и упаковка
не проверялись. Node smoke подтверждает WASM binding на подменённом Tauri API,
а native тесты — сервис заданий и транспорт. Он не является end-to-end тестом
между WebView и host. Linux/macOS runtime, физические Kobo/Kindle и настоящая
конвертация не проверялись на этом этапе; проверки перенесены в №15.
Остановка по-прежнему может ждать непрерываемого системного вызова.
Коммит/PR не создан.
