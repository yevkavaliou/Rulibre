# Appearance corrections after item 13

12 October 2026: user approved these changes in this chat after reviewing the item 13 debug build. The HTML reference was updated before implementation. These amendments are additional work on the existing screens; item 14 has not started.

- Settings → Text size: 14, 16, 18 or 20 logical pixels for the base UI text; default 16. Titles, secondary text and hints keep their relative sizes. This adjusts fonts independently of OS DPI, not the whole window scale. List rows and Unicode ellipsis measurement follow the chosen size.
- Settings → Cover size: 120, 160 or 200 logical pixels wide; default 160. Both the grid and book details use this width. The grid computes columns, row heights, visible books and thumbnail requests from the same geometry.
- Drag the divider beside the book details to resize the right pane. Default width is 300, allowed range 240–480 logical pixels. The actual width is bounded by the window/sidebar and space for at least one configured cover card. During dragging the layout updates immediately; the preference is atomically saved on release. A failed save restores the previous width. Losing focus cancels an unfinished drag. Saved width is preserved when a narrower window temporarily constrains it.
- Convert has a distinct menu background and border. Available routes use light text on blue buttons; unavailable routes use readable grey text and explicit “no route”. Hover tooltips keep the backend diagnostics on a bounded contrasting surface.

Settings are saved through the existing serialized writer. Older `ui.toml` files receive the defaults; out-of-range appearance values are bounded on load. The default width and font/cover settings do not require changing the user's configuration manually.
