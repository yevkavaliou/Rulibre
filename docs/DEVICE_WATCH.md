# Наблюдение за устройствами (этап №10)

Проверено 11 октября 2026 года на Windows. Общий модуль
`rulibre_core::device_watch` не зависит от TUI, Tauri или executor.

## Снимки и выбор

`DeviceTracker::poll` принимает `Result<DiscoveryReport, Error>`. Сравнение
выполняется по `DeviceId` из этапа №9, а затем по всем полям `Device`.
Изменение пути, метки, типа файловой системы, read_only или evidence при том же
ID создаёт `Changed { previous, current }`. Другой ID на том же пути создаёт
`Disconnected(old_id)` и `Connected(new_device)` за один опрос. Порядок событий
детерминирован: удаления/изменения по ID, затем подключения по ID.

Транспортный `DeviceEvent` общий с WASM frontend:

- `Snapshot { devices, selected_id, changes, warnings }` — полный актуальный
  список и изменения. Первое успешное чтение публикуется даже для пустого списка.
  Неизменный снимок повторно не публикуется.
- `PollFailed { diagnostic }` — ошибка перечисления. Повтор одинаковой ошибки
  подавляется; успешное восстановление всегда публикует снимок.

Выбранный ID хранится отдельно от снимка. Если он присутствует в новом списке,
выбор сохраняется, включая появление второго устройства; параметры выбранного
устройства обновляются. Если ID исчез, выбор сбрасывается. При отсутствии выбора
автоматически выбирается только единственное устройство. При нескольких ридерах
выбор остаётся пустым. `DeviceTracker::select` позволяет явно выбрать ID из
последнего успешного снимка; неизвестный ID и выбор во время ошибки отклоняются.
Существующие клиенты используют автоматический выбор; экран выбора не добавлен.

При ошибке опроса выбранное устройство сбрасывается сразу, чтобы клиент не
использовал непроверенное назначение. Последний успешный список сохраняется
только для сравнения после восстановления. Переподключение не восстанавливает
выбор среди нескольких устройств; единственное устройство выбирается снова.
Предупреждения отдельных томов передаются в Snapshot. Устройство, которое больше
не удалось распознать, отсутствует в актуальном списке и теряет выбор.

Идентичность имеет ограничения из [DEVICE_DETECTION.md](DEVICE_DETECTION.md):
на Windows это ID тома, на Linux обычно UUID, на macOS идентификатор зависит от
источника тома. Это не гарантированный серийный номер физического ридера. Замена
двумя устройствами с одинаковыми ID и всеми полями неотличима. Короткое отключение
и возврат между двумя опросами также может остаться незамеченным.

## Поток и завершение

`DeviceWatcher::start` создаёт отдельный именованный std-поток. Первый опрос
выполняется сразу; TUI и Tauri задают двухсекундную задержку после опроса.
`start_with` принимает подменяемый detector и callback; false от callback
завершает поток. TUI возвращает false при закрытом канале событий.

`stop` посылает сигнал, прерывает ожидание следующего опроса и выполняет join;
повторный stop допустим. Drop также останавливает и присоединяет поток. После
запроса остановки результат текущего опроса не публикуется. Уже начавшийся callback
может завершиться; после возврата stop новых callbacks нет.

TUI явно останавливает наблюдатель после `App::run`; Drop покрывает ранние ошибки.
Tauri хранит наблюдатель в managed state и удаляет его на `RunEvent::Exit`.
Обнаружение не выполняется на UI-потоке или async runtime. Host обновляет текущий
Device перед отправкой события; оба клиента применяют `selected_device()` и
`message()` из общего транспортного контракта.

Синхронный системный вызов перечисления/чтения файлов нельзя принудительно
прервать. Stop ждёт возврата текущего detector/callback; жёсткого timeout
завершения при зависшем системном вызове нет. Отмена копирования и задания остаются
этапами №12–13. Проверка актуальности прямо перед записью остаётся этапом №12.

## Проверки

- `cargo test --locked`: 66 успешных тестов, включая 10 новых тестов наблюдателя;
  3 прежних ignored-теста не запускались.
- `cargo check --locked`: ядро, TUI и scan_metadata успешно.
- `cargo fmt -p rulibre-core -p rulibre -- --check`: успешно.
- `cargo clippy --locked -p rulibre-core -p rulibre --all-targets`: успешно;
  прежние предупреждения metadata.rs и Default в TUI остаются, новых нет.
- `cargo check --locked -p rulibre-gui` и `cargo test --locked -p rulibre-gui`:
  успешно, 3 теста транспорта. Тест устройства проверяет полный снимок,
  подключение, отключение, изменение пути, предупреждение и PollFailed через
  сериализацию в модель frontend, включая общий текст сообщения.

Покрыты подключение, отключение, переподключение, замена без пустого опроса,
изменение пути и атрибутов, несколько устройств и сохранение/сброс выбора,
порядок снимка, временная ошибка и восстановление, предупреждения, stop во время
длинной задержки и текущего опроса, Drop, закрытый потребитель и выполнение вне
вызывающего потока. Тесты используют подмену опроса и каналы синхронизации;
физические устройства не требуются.

Проверки выполнялись вне Windows sandbox, с TMP/TEMP в `target/issue10-tmp`.
В sandbox файловые тесты прежних этапов получают Access denied при разрешении
путей/замене файлов. Для Tauri временно создавались `icons/icon.ico` и `dist/index.html`;
после проверки они удалены. Форматирование изменённых GUI-файлов выполнено
rustfmt со `skip_children=true`, без общего форматирования GUI.

WASM target отсутствует; frontend сборка, запуск окна/IPC, Linux/macOS runtime и
подключение физических Kobo/Kindle не проверялись. Сериализация общих моделей
проверена host-тестами, что не заменяет WASM/GUI smoke-test в этапе №15.
Коммит/PR не создан.
