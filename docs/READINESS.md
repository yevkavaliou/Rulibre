# Итоговая готовность ядра

Пункт №15 PRE_UI_PLAN.md. Проверка 12 октября 2026 года, Windows 11/MSVC,
Rust/Cargo 1.93.1, установленный wasm32-unknown-unknown.

> **После №17 UI_PLAN.md** клиент Tauri/Leptos и WASM-проверки удалены. Ниже сохранён
> результат прогона на момент №15; строки про Tauri, WASM и `-WasmIpc` относятся к
> удалённому коду и повторно не воспроизводятся. Актуальные команды:
> `scripts/check-readiness.ps1` (ядро, TUI, native volumes; флаги `-RealConverters`, `-Ui`)
> и `scripts/check-ui.ps1` (iced UI). См. также матрицу UI в конце файла.

## Решение

Ядро готово к разработке нового UI в пределах проверенных контрактов Windows.
Обязательные локальные автоматические проверки успешны. Не обнаружены известные
критические ошибки, завершающие приложение при ожидаемой ошибке, распознающие
обычный диск как ридер или молча перезаписывающие существующие данные.
Это заключение по выполненным сценариям, а не доказательство отсутствия всех ошибок.
Поддержка всех физических устройств и runtime на Linux/macOS пока не подтверждена.

CI настроен для Windows, Ubuntu 24.04 и macOS; удалённые запуски в этой работе
не выполнялись. Workflow начнёт проверку после push/PR либо workflow_dispatch.
Его наличие не считается успешным результатом Linux/macOS.

## Изменения и воспроизведение

Добавлен тест `transfer::tests::readiness_pipeline_preserves_library_across_success_and_expected_failures`.
Он использует копию синтетической библиотеки, сохранение/загрузку конфигурации,
валидацию библиотеки, фоновые scan/metadata, распознавание Kobo по фикстуре тома,
подготовку существующего KEPUB и настоящие файловые операции безопасной передачи.
Проверяются равенство переданных байтов, конфликт без замены, отсутствие маршрута
при пустом наборе конвертеров, отмена после события копирования, имитация потери
тома и диагностика оставшегося .part. Снимки всех исходных файлов сравниваются
после каждой ветки; существующая переданная книга сохраняется. Потеря тома и
отсутствие инструментов внедряются через приватные точки подмены, без изменения
глобального PATH и без выдачи каталогов за реальные USB-устройства.

Отдельные ранее добавленные тесты проверяют отказ записи, частичную запись,
отсутствующий mount root, junction/символические ссылки, обычные диски, очереди,
конфликт заданий, состояния, отмену процессов, shutdown и устаревшие ответы клиентов.
Они включены в итоговый прогон. Устранены прежние предупреждения Clippy в
metadata/TUI; ядро/TUI проверяются с `-D warnings` и `--all-targets`.

Общий скрипт `scripts/check-readiness.ps1` вызывает проверки клиентов №14,
строгий Clippy и отдельный native volume smoke. (На момент №15 флаг `-WasmIpc`
запускал WASM binding в Node.js; он удалён в №17.) `-RealConverters` явно включает
установленный Calibre; отсутствие нужной возможности приводит к провалу smoke,
а не к ложному успеху. Этот флаг не включён в обязательный CI.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-readiness.ps1 -RealConverters
```

Полный журнал: [readiness/windows.log](readiness/windows.log).
Для сохранения native stdout/stderr используется внешняя оболочка с
`*>&1 | Tee-Object`; PowerShell Transcript в этой среде не записывает вывод Cargo.
В CI журналы сохраняются как отдельные artifacts для каждой ОС даже при ошибке.

Настоящий smoke Calibre использует валидный TXT из фикстуры и создаёт EPUB,
после чего преобразует его в KEPUB. Он подтверждает выполнение маршрута и
сохранность библиотеки, но не качество отображения книги на ридере.
Ignored helper subprocess запускается своим автоматическим тестом; его нельзя
включать произвольным `cargo test -- --ignored` вместе со всеми smoke-тестами.

Windows проверки выполнялись вне sandbox: внутри него canonicalize, файловые
handles, junction и поиск конфигурации Clippy получают Access denied.
TMP/TEMP/TMPDIR тестов ограничены `target`. GUI check создаёт только отсутствующие
dist/icon.ico как временные build fixtures и удаляет их после проверки.
Это не готовые ресурсы поставляемого приложения. Предупреждения GUI о
неиспользуемых общих моделях и hard-link cache сохраняются; строгий Clippy в
этом этапе относится к ядру/TUI, не ко всему GUI workspace.

## Сверка этапов и API

Примечания №1–14 остаются историей результатов соответствующих этапов.
Их перенесённые проверки сведены в матрицу выше: WASM теперь доступен и проверен,
настоящий Calibre повторно проверен, прежние предупреждения Clippy исправлены.
Ограничения физических устройств, Linux/macOS и поставляемого GUI остаются явными.
Новый тест связывает контракты конфигурации, книг, метаданных, обнаружения,
подготовки, передачи и заданий; финальные тесты включают регрессии всех этапов.

README обновлён: точный набор форматов (CBZ не поддерживается), зависимости
конвертации, read-only библиотека, lifetime временных результатов, устройства,
ручной выбор в core API, ошибки и задания. Ссылки на документацию модулей
собраны в README. Существующие клиенты ещё не имеют экрана ручного выбора.

Сохраняются ограничения API: отмена кооперативная, shutdown может ожидать
непрерываемого системного вызова, резервирование назначения действует в одном
executor, каналы событий нужно регулярно читать. После отключения очистка .part
может быть невозможна; путь и причина доступны в PartialTransfer.

Для последующей физической проверки подключить один Kobo/Kindle, отдельно
зафиксировать ОС, модель, прошивку, тип файловой системы, evidence обнаружения;
передать валидную тестовую книгу, проверить открытие на ридере, повторить передачу
для конфликта и сравнить исходную библиотеку. Отмену/USB-отключение проверять только
на тестовых книгах; после подключения проверить отсутствие ложного конечного
файла и диагностированный .part. Сейчас эти проверки не заявляются успешными.
Коммит/PR не создан; CI не отправлен на GitHub.
