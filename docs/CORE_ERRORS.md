# Контракт ошибок ядра — этап №3

Дата: 11 октября 2026 года.

`rulibre_core::Error` содержит `operation`, необязательный `path: PathBuf`
и `kind: ErrorKind`. Категории: `Io`, `InvalidData`, `Unavailable`,
`InvalidInput`, `ExternalProcess`. `Io` сохраняет `std::io::Error`, включая
`ErrorKind` и код ОС; ошибки TOML/XML сохраняют исходную ошибку через `source()`.
Сбой процесса сохраняет программу, `ExitStatus` и исходные байты stderr.
Ошибки запуска процесса возвращаются как `Io` с операцией запуска программы.
`Display` даёт диагностическое представление; уведомления об успехе формируют
клиенты. Ядро не печатает ошибки и не завершает процесс.

## Изменённые публичные сигнатуры

| API | Результат |
| --- | --- |
| `Config::path()` | `Result<PathBuf, Error>` |
| `Config::load()` / `load_from(path)` | `Result<Option<Config>, Error>` |
| `Config::save()` / `save_to(path)` | `Result<(), Error>` |
| `config::is_calibre_library(path)` | `Result<bool, Error>` |
| `scanner::scan_library(path)` | `Result<ScanReport, Error>` |
| `scanner::scan_formats(path)` | `Result<String, Error>` |
| `metadata::parse_opf(path)` | `Result<Option<Metadata>, Error>` |
| `converter::find_source_file(path)` | `Result<Option<PathBuf>, Error>` |
| `converter::convert(...)` | `Result<(), Error>` |
| `DeviceState::send_book(...)` | `Result<PathBuf, Error>` — путь назначения |

`Ok(None)` означает отсутствие конфигурации/OPF или отсутствие исходного файла
в успешно прочитанном каталоге. Повреждённый TOML/XML, отсутствие элемента
metadata, ошибки чтения и записи возвращают `Err`. Пустой каталог при
сканировании даёт успешный пустой результат. Проверка Calibre возвращает
`Ok(false)` для отсутствующего пути/metadata.db или неподходящего типа файла,
но не скрывает ошибки доступа.

`ScanReport` содержит `books` и `warnings: Vec<Error>`. Невозможность прочитать
корень или получить очередную запись корня — критическая ошибка. Ошибки
подкаталогов авторов, книг, чтения форматов и метаданных файлов — предупреждения;
остальные книги продолжают сканироваться. OPF читается отдельным вызовом
`parse_opf`; сканирование каталога не проверяет содержимое OPF.

## Клиенты и проверки

TUI обрабатывает ошибки настройки, метаданных, конвертации и передачи, показывает
предупреждения сканирования. Ошибки инициализации возвращаются в `main` до
включения raw mode. `scan_metadata` различает отсутствующий и повреждённый OPF,
печатает предупреждения и завершает процесс только на границе CLI.
Tauri преобразует ошибки в строковые IPC rejection, передаёт книги и предупреждения
в отдельной транспортной структуре. Изменённые WASM-вызовы перехватывают rejection
и показывают ошибки в существующих элементах интерфейса.

Проверки на Windows:

- `cargo test --locked`: 15 тестов проходят (6 исходных и 9 новых).
- `cargo check --locked`: ядро, TUI и `scan_metadata` проходят.
- `cargo fmt -p rulibre-core -p rulibre -- --check`: проходит.
- Изменённые GUI-файлы отдельно отформатированы rustfmt.
- `cargo check --locked -p rulibre-gui`: проходит при временных тестовых
  `icons/icon.ico` и `dist/index.html`; они удалены после проверки. Без них
  сохраняются исходные ограничения сборки, найденные в №2. Это проверка типов
  host, не сборка frontend, упаковка или проверка IPC в работающем окне.
- WASM check по-прежнему недоступен: отсутствует `wasm32-unknown-unknown`.

Новые тесты проверяют отсутствующий и ошибочный корень, пустые каталоги,
ошибки поиска исходного файла, повреждённый и нечитаемый конфиг/OPF,
ошибки сохранения, отсутствие устройства, ошибку подготовки/записи на устройство,
одиночные кавычки и ошибку запуска конвертера. Отдельный тест использует
реальную Windows-блокировку файла OPF (sharing violation). Отказ доступа к книге
подменяется в приватном чтении форматов: проверяется сохранение PermissionDenied
и продолжение обхода других книг. Это не проверка ACL каталога или физического ридера.

## Границы этапа

Сохранение конфигурации пока не атомарно (№4); расширенные правила путей также
относятся к №4. Исправлена только паника на одиночной кавычке, поскольку это
ожидаемый пользовательский ввод. Успех `convert` пока означает нулевой exit
процесса, без проверки созданного файла (№8). Проверки доступности backend и
автообнаружение устройства сохраняют прежние probe API до №7/№9.
Безопасная публикация и конфликты копирования относятся к №12.
Полная проверка WASM, остальных IPC-вызовов и состояния выбора — №14/№15.
Настоящие конвертеры и физические устройства на этом этапе не проверялись.
Коммит/PR не создан.
