# Библиотека Calibre только для чтения

Проблема №7, 11 октября 2026 года.

Rulibre не добавляет форматы в каталог книги и не редактирует `metadata.db`
или OPF. Конвертация создаёт отдельный результат; список `Book.files` остаётся
снимком исходной библиотеки. Интеграция с `calibredb` сюда не входит.

## API и размещение результатов

```rust,ignore
let workspace = converter::Workspace::new(&library_root)?;
let result = converter::convert(
    &library_root, workspace.path(), &source_file, Format::Epub,
)?;
// Использовать result, пока workspace жив.
```

После этапа №8 `convert(library_root, output_dir, source_file, target)` возвращает
`ConversionResult` с проверенным `output_path`, размером, источником, целью и backend.
Каталог результата должен уже существовать. Маршруты, публикация без перезаписи
и отмена описаны в [CONVERSION.md](CONVERSION.md).
Для постоянного экспорта вызывающий код передаёт явно выбранный пользователем
каталог вне библиотеки. Такой результат принадлежит вызывающему коду и
автоматически не удаляется. Существующие файлы, каталоги и ссылки с конечным
именем отклоняются до запуска процесса. Совпадение результата с источником
запрещено, в том числе при попытке конвертации в тот же формат рядом с источником.

Корень библиотеки и каталог результата канонизируются: проверяются относительные
пути, `..`, symlink и Windows junction. Вывод внутри указанного корня или другой
библиотеки с `metadata.db` в предках запрещён. Ошибки доступа возвращаются,
проверки не трактуют их как отсутствие файла. `library_root(book_path)` находит
корень по `metadata.db` в предках; клиенты используют его перед конвертацией.

`Workspace::new` создаёт уникальный каталог
`<std::env::temp_dir()>/rulibre-conversion-<pid>-<counter>`.
`Workspace::in_directory` позволяет явно передать существующую рабочую базу.
База проверяется до создания подкаталога; если системный TEMP находится внутри
библиотеки, возвращается ошибка. Чужие существующие каталоги не используются.

Для KEPUB задаётся конкретное имя `*.kepub.epub`, для остальных целей —
расширение выбранного формата. `kepubify -o` принимает несуществующий выходной
файл для одного входного файла согласно [документации kepubify](https://pgaskin.net/kepubify/docs/).

## Время жизни и очистка

- Подготовка для устройства возвращает путь вместе с владельцем workspace.
  Каталог жив до завершения копирования и удаляется при успехе или ошибке.
  Готовый совместимый файл используется прямо из библиотеки без workspace.
- Конвертация в TUI сохраняет workspace в состоянии приложения до его удаления;
  Tauri host хранит workspace в состоянии приложения и очищает их на `RunEvent::Exit`.
  Сообщение показывает временный путь и предупреждает об удалении при выходе.
  Форматы книги в TUI/GUI после конвертации не обновляются.
- Неуспешная конвертация в этих сценариях удаляет workspace вместе с частичными
  файлами. `Workspace::cleanup()` возвращает ошибку удаления; `Drop` повторяет
  очистку и пишет ошибку в stderr, если она не удалась.
- Принудительное завершение процесса, отключение питания или заблокированные
  файлы могут оставить временный каталог. Автоматическое удаление каталогов
  других процессов/предыдущих сессий не реализовано; остатки можно удалить
  вручную после завершения Rulibre. Постоянный экспорт очищает вызывающий код.

## Проверки и ограничения

`cargo test --locked --offline`: 41 тест прошёл, один тест реального конвертера
по умолчанию игнорируется. Семь новых автоматических тестов покрывают сохранность
всех имён/байтов файлов библиотеки (включая `metadata.db`, OPF и исходные книги),
очистку успешных и частичных результатов, постоянный экспорт и конфликт имени,
запрет небезопасных каталогов, Windows junction в библиотеку, время жизни
результата при копировании и запрет корня библиотеки как mount point назначения.
Существующий тест передачи готовых файлов дополнен снимком библиотеки.

`cargo check --locked --offline` и
`cargo fmt -p rulibre-core -p rulibre -- --check` прошли.
Проверки выполнялись вне Windows sandbox: внутри него `canonicalize` возвращал
отказ доступа даже для workspace, а rustfmt не мог заменить файлы.
TMP/TEMP для тестов установлен в `target/test-tmp`.

Tauri host: `cargo check --locked --offline -p rulibre-gui` и
`cargo test --locked --offline -p rulibre-gui --bin rulibre-gui` прошли
(один тест сериализации нового `ConvertOk { message, output_path }`).
Использовались временные тестовые icon.ico/dist; после проверки они удалены,
прежние файлы generated schemas сохранены. Запуск окна/реальный IPC не проверен.
WASM target отсутствует; frontend адаптирован в коде, его сборка не подтверждена.

Отдельно прошла реальная конвертация синтетического TXT → EPUB установленным
Calibre `ebook-convert` 8.16.2: результат ненулевой, библиотека не изменилась,
workspace удалился. Воспроизведение:

```powershell
cargo test --locked --offline -p rulibre-core real_ebook_convert_keeps_library_read_only -- --ignored --nocapture
```

`kepubify` отсутствует; его запуск проверен подменой процесса. Настоящие ридеры,
Linux/macOS не проверены. Набор форматов/маршрутов, проверка наличия и размера
результата в общем API и отмена процесса реализованы в №8; Kobo-приоритеты —
№11, защита конечного пути передачи — №12, конфликты параллельных заданий — №13.
Предварительная проверка пути не защищает от его конкурентной подмены другим
процессом; рабочие каталоги следует размещать в доверенной файловой системе.

Коммит/PR не создан.
