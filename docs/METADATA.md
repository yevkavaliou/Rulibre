# Чтение метаданных (этап №6)

## Контракт и приоритет

`metadata::parse_opf(&Path)` читает только `metadata.opf`:

- `Ok(None)` — файл отсутствует.
- `Ok(Some(Metadata))` — XML разобран, найден `metadata` в OPF namespace
  `http://www.idpf.org/2007/opf` либо без namespace.
- `Err(Error)` — ошибка чтения или XML/структуры с операцией и путём OPF.
  Недоступный файл не считается отсутствующим. Невалидный UTF-8 возвращается
  как I/O `InvalidData`; повреждённый XML — как `ErrorKind::InvalidData`.

DC-поля распознаются по URI namespace, независимо от имени префикса.
Название — первое непустое `dc:title`; авторы — все непустые `dc:creator`
в порядке документа. Краевые пробелы удаляются. Пустые авторы пропускаются.
Calibre series/series_index/rating читаются из `meta` в OPF namespace или без
namespace; чужой namespace не может подменить их. Для одиночных полей, кроме
названия, при повторении сохраняется последнее значение.

`metadata::read_metadata(&Path)` добавляет fallback независимо для каждого поля:
название из имени каталога книги без положительного числового Calibre ID
` (42)`, автор из имени родительского каталога. Непустые OPF-поля имеют приоритет.
При отсутствии OPF возвращаются только эти имена, остальные поля пусты.
При ошибке OPF функция возвращает ошибку; её нельзя принять за отсутствие файла.
`Metadata::with_fallback(title, author)` позволяет клиенту добавить эти значения
к уже прочитанным метаданным или создать минимальные данные для отображения.

Сканер применяет тот же приоритет к `Book.title` и `Book.author`; нескольких
авторов объединяет через `, `. ID, пути и файлы книги от метаданных не зависят.
При ошибке OPF книга остаётся в списке с именами каталогов, ошибка попадает
в `ScanReport.warnings`. Отсутствующий OPF предупреждения не создаёт.
TUI показывает fallback и уведомление при ошибке. Tauri сохраняет транспортный
контракт `Result<Option<Metadata>, String>`: успешное чтение теперь всегда
`Some`, включая отсутствие OPF; ошибка возвращается клиенту. Панель GUI
использует имена выбранной книги, если метаданные недоступны.
`scan_metadata` продолжает использовать сырой `parse_opf`, чтобы отдельно
сообщать об отсутствующих, повреждённых и неизвестных метаданных.

## Описание и диагностика

Экранированный HTML, CDATA и вложенный XHTML преобразуются в обычный текст
HTML-парсером kuchikiki/html5ever. Именованные и десятичные/шестнадцатеричные
числовые сущности декодируются на уровне HTML один раз (после XML-декодирования).
Например, HTML `&amp;lt;` остаётся текстом `&lt;`, не превращается в тег.
Неизвестные HTML-сущности сохраняются как текст.

Абзацы и основные блоки разделены пустой строкой, `br` — переводом строки,
строки списков/таблиц — переводом строки, ячейки — пробелом. Пробельные символы
в текстовых узлах схлопываются; края строк и всего описания обрезаются.
Комментарии, script, style, head и template исключены. HTML не исполняется.
TUI выводит строки описания отдельно; GUI уже использует `white-space: pre-wrap`.

Неизвестные XML-теги сохраняются в `Metadata.unrecognized` с URI namespace.
Неизвестные `meta[name]` сохраняют name/content; `meta[property]` — property/text.
Диагностика доступна `scan_metadata` и отладочным панелям клиентов.

## Проверки и ограничения

На Windows прошли **34 теста** ядра, включая 6 новых интеграционных тестов:
отсутствие OPF, пустые поля, namespace и другой namespace, несколько авторов,
серия/индекс/rating, идентификаторы, неизвестные теги, приоритет имён,
повреждённый OPF, неизменность файлов/ID, Windows sharing violation,
экранированный HTML/CDATA/XHTML, абзацы, переносы, сущности, атрибут с `>`,
неполный HTML и исключение невидимого содержимого.

Команды: `cargo test --locked --offline`, `cargo check --locked --offline`,
`cargo fmt -p rulibre-core -p rulibre -- --check`; все прошли.
В песочнице тесты запускаются с TMP/TEMP внутри workspace:

```powershell
New-Item -ItemType Directory -Force target/test-tmp | Out-Null
$env:TMP = (Resolve-Path target/test-tmp).Path
$env:TEMP = $env:TMP
cargo test --locked --offline
```

Первый запуск со стандартным sandbox Temp дал отказ доступа при замене конфига
в существующем тесте №4; с workspace Temp все проверки прошли. rustfmt выполнен
вне песочницы из-за отказа доступа при замене файлов. Tauri host
`cargo check --locked --offline -p rulibre-gui` прошёл вне песочницы (build script
не мог canonicalize файл из Cargo cache внутри неё), с временными тестовыми
icon.ico/dist, удалёнными после проверки.

WASM target отсутствует, сборка frontend и smoke-test IPC не подтверждены.
Linux/macOS, настоящие ридеры и конвертеры не проверялись.

Парсер ориентирован на Calibre OPF 2: OPF 3 refinements/roles не интерпретируются
и остаются в диагностике, `dc:creator` считается автором независимо от role.
Идентификаторы сохраняют прежнюю политику: scheme из `opf:scheme`, иначе `ID`;
внутренние `calibre` и `uuid` исключены. Идентификаторы не валидируются.
HTML-разметка, оформление, URL ссылок, изображения и исходное форматирование
`pre` не сохраняются: результат — читаемый текст, а не точная копия страницы.
Не выполняется запись в OPF/Calibre DB. Добавлена прямая зависимость kuchikiki
из уже зафиксированной версии Cargo.lock; версии пакетов не обновлялись.
Коммит/PR не создан.
